# Aceitação — M34, eval de descobribilidade

Mede se uma skill é encontrada pela intenção que deveria encontrá-la, **sem executá-la**, e diz a
causa quando não é.

## Alvo

Duas metades, ambas exercitadas contra o artefato real:

- **A superfície de autoria** — `app-dev.usetheo.dev/skills/nova`, dashboard `6e147fc`.
- **O gate** — API do `theo-skills` em `develop` (com os fixes deste ciclo) contra o
  `theoskill_pgvector`. Acervo e banco reais; nenhum mock.

## AC1 — Dataset versionado, datado, contra o acervo real — `passed`

`version: 2`, `dated: 2026-08-04`.

**Este critério estava falso e só apareceu porque foi medido.** A v1 apontava para
`sk_cambio_v1` — que existe apenas no `seed()` de
`tests/integration/m34-discoverability.integration.test.ts` — enquanto o próprio campo
`_honestidade` do dataset afirmava, textualmente:

> "Roda contra o **ACERVO REAL** do workspace, não contra fixture."

Um dataset que semeia a skill que vai procurar mede o semeador, não a descoberta.

Corrigido em duas frentes: os identificadores passam a ser do acervo real, e o runner consulta se
cada skill ainda existe. Uma que saiu do acervo é reportada e **não** conta como regressão — ver
AC5, run 3.

## AC2 — Nomeia a causa, não o número — `passed`

Medido no `app-dev`, publicando de verdade:

```
POST /v1/dashboard/skills/:discoverability → 200
{"discoverable": false,
 "causes": ["no_embedding"],
 "hints": ["A revisão vigente não tem vetor: a skill só aparece para quem já sabe o nome dela…"],
 "embedder": "openai/text-embedding-3-small"}
```

A tela mostra `DIFICILMENTE ENCONTRADA`, a frase da causa, e **qual embedder mediu** — o
requisito que o risco 1 do roadmap impôs, para que um número produzido sob um embedder não seja
comparado com outro.

## AC3 — Roda no momento da autoria — `passed`, com defeito filado

O card **"Será encontrada?"** aparece em `/skills/nova` depois do `:validate` e **antes** do
Publicar — o mesmo lugar onde o `field`/`line` do M30 já responde.

**Defeito observado e filado ([theo-skills#144](https://github.com/usetheoai/theo-skills/issues/144)):**
em contexto pré-publicação a tela envia `has_embedding: false` fixo — porque a skill ainda não
existe — então `no_embedding` **sempre** dispara, e o hint manda *"Republique para gerar o
vetor"*, instrução impossível para algo nunca publicado.

A causa que sempre dispara é justamente a única que o autor **não pode** resolver naquele
momento, e ela domina o veredito. O mecanismo cumpre o critério; o que ele diz naquele contexto
ainda não é acionável.

## AC4 — Nenhuma execução da skill — `passed`

A fronteira é declarada **ao usuário**, não só no código: *"Este diagnóstico compara a skill com o
acervo — e **não a executa**."*

Verificável no payload: só viajam `name`, `description` e `has_embedding`. Não há script,
sandbox nem runtime no caminho.

## AC5 — Regressão detectada: reprova o gate — `passed`

Demonstrado ponta a ponta, com **degradação real do sistema** — não com um teste que simula a
degradação:

| Run | O que fiz | Saída | Exit |
|---|---|---|---|
| 1 | nada (estado normal) | `1/1 achadas` · `#1` | `0` |
| 2 | **depreciei** a skill (`PUT …/lifecycle`) | `REGRESSÃO: 1 skill(s) deixaram de ser achadas` | **`1`** |
| 3 | **apaguei** a skill (`DELETE`) | `fora` · "não contam como regressão" | `0` |

O run 2 é o critério literal. O run 3 é a distinção que o AC1 exigiu: *"a descoberta piorou"* e
*"não há o que descobrir"* são fatos diferentes, com donos diferentes.

**Antes do fix deste ciclo, o run 1 teria dado `0/1`** — o runner lia `body.skills` e a busca
devolve `results`. A baseline seria de zeros, e dali em diante nenhuma regressão seria
detectável: não há como regredir de "nunca achada". **O gate era inerte, e um gate que não pode
reprovar é pior que gate nenhum — ocupa o lugar de um.**

## O que este milestone me ensinou sobre mim

Dois dos defeitos corrigidos aqui eram **meus, escritos no mesmo dia**: o runner lendo `skills` em
vez de `results`, e o dataset apontando para a própria fixture enquanto afirmava o contrário.

Os dois compartilham a causa: **inferi a forma em vez de medi-la**, e escrevi a afirmação de
honestidade antes de verificar se ela era verdadeira. Nenhum teste pegou — `eval/` fica fora do
`tsconfig` e, pior, os dois arquivos de teste em `src/` **nunca rodavam no CI** (o `include` do
vitest só alcançava `tests/contract/**`). O `regression-gate.test.ts`, que eu havia reportado como
"6 passed", nunca tinha sido executado pelo CI uma única vez.

Isso também foi corrigido: `31 → 33` arquivos, `166 → 181` testes.
