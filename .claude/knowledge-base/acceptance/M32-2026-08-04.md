# Aceitação — M32, ciclo de vida da skill

Valida a entrega do `theo-skills 0.13.0` (tag `v0.13.0`, merge commit `9a39a1c`).

## Alvo: o artefato released, não a árvore de trabalho

**`git worktree add /tmp/acc-m32 v0.13.0`** → `pnpm install --frozen-lockfile` → `pnpm -r build` →
exercitado contra o Postgres do projeto. Nenhum critério foi exercitado contra a árvore de
trabalho, contra mock ou contra `pnpm dev`.

**Por que não o `app-dev`, e isso é um limite declarado.** O `app-dev.usetheo.dev` serve o
**theo-cloud** — medido: `GET /v1/version` responde `{"name":"theo-cloud", ..., "node":"go1.26.5"}`.
As rotas `/v1/skills*` existem lá (respondem **401**, não 404), portanto o registry é alcançável por
proxy do control plane, mas exigem credencial de escopo `skills:read` por inquilino que **não
existe** no ambiente (`env` e `.env` verificados, ambos sem chave). É o mesmo bloqueio que mantém o
**M7** aberto desde 2026-08-03.

Consequência honesta: **este registro não afirma que o M32 está validado no `app-dev`.** Ele afirma
que está validado no artefato released, que é o alvo previsto por `cycle-acceptance § Target kinds`
para pacote interno — e o mesmo caminho que o M31 usou e teve aceito.

## Critérios

Evidência bruta: `evidence/M32-2026-08-04-tag-v0.13.0.txt`

### AC1 — Duas dimensões ortogonais, não um enum só — `passed`

O contrato de leitura devolve os dois eixos separados:

```
AC1 dois eixos no contrato : {"lifecycle":"deprecated","enabled":true}
```

Uma skill pode estar **descontinuada e habilitada** ao mesmo tempo — que é a prova de que os eixos
não colapsaram. A tabela de combinações válidas está no ADR D1 do plano; as duas CHECK constraints
foram verificadas rejeitando no banco (estágio fora do vocabulário e `deprecated` sem motivo).
Migração aditiva confirmada: 3/3 linhas pré-existentes herdaram `active` + habilitada.

### AC2 — Deprecada continua resolvível — `passed`

```
AC2 deprecada RESOLVE por id : true
```

Exercitado pelo **caminho de produção** (`skills-store.getView`), não por SQL. A distinção não é
acadêmica: a versão anterior deste teste consultava a tabela direto e **passava verde** com a
garantia quebrada — provado durante o review, quando uma injeção de `eq(lifecycle,'active')` no
`getView` não derrubou nenhum teste. O teste corrigido reprova essa mesma injeção.

### AC3 — Descoberta exclui por padrão, com opt-in — `passed` com caveat

```
AC3 busca padrao (so ativas) : ["nova"]
AC3 busca com opt-in total   : ["nova","rascunho","velha"]
```

O padrão devolve só a ativa; o opt-in total devolve as três. A capacidade não foi perdida — apenas
o default mudou.

**Caveat (defeito de processo, não de código):** a DoD exige que a mudança de comportamento seja
*"anunciada **antes** de virar default"*. Opt-in e novo default foram entregues **no mesmo release**.
Não há como desfazer isso retroativamente. Mitigação parcial: a quebra está marcada `BREAKING:` no
CHANGELOG e no corpo do release. Issue filada.

### AC4 — Motivo e sucessora viajam no contrato — `passed`

```
AC4 motivo no contrato de leitura : "substituida por nova"
AC4 sucessora no contrato         : "nova"
```

**Este critério estava falso até horas atrás, e só apareceu porque foi medido.** Os campos existiam
na resposta da API e os tipos `Skill` (SDK) e `SkillSummary` (MCP) **não os declaravam** — um campo
que o tipo não declara é uma porta fechada, por mais que o corpo HTTP o contenha. Corrigido em
`b8da764`, com teste que assere também que **ausência ≠ `active`** (um registry antigo simplesmente
não manda o campo).

Limite: verificado em SDK e MCP. O **CLI** não foi exercitado — ele consome o SDK, então herda os
tipos, mas isso é inferência e não medição.

### AC5 — A tela diz o que deixa de valer — `not_exercised`

**Não entregue, e deliberadamente fora do escopo deste milestone.** O `CLAUDE.md` deste repositório
proíbe frontend aqui; a tela nasce em `theo-cloud/dashboard` e é trabalho do **M33**, que declara o
M31 como dependência. O plano registrou isso como nota de fronteira antes da implementação começar,
não como descoberta posterior.

O que este repositório devia entregar para viabilizá-la — estágio, motivo e sucessora no contrato de
leitura — está entregue (AC4).

## O que este milestone provou sobre o próprio processo

Três vezes, algo **verde** afirmou sucesso que não existia:

1. O teste de regressão do Goal passava com a garantia quebrada (SQL cru em vez do caminho de produção).
2. Um achado foi **declarado corrigido** e medido como aberto (o `BREAKING:` com prefixo errado).
3. O override de CVE ficou no manifest, o `install` reportou sucesso, e a árvore resolvida não mudou.

Nenhum dos três foi pego pelos 42 testes iniciais. Todos foram pegos por **medição independente** —
o que justifica o custo do `/review` com agentes e da re-verificação.

## Verdict

**`NOT_VALIDATED`** — computado por `compute_acceptance_verdict.py`, não asserido.

```
- AC5: not_exercised — the live system was not exercised for it.
NOT_VALIDATED
```

**Correção de um erro deste próprio documento.** A primeira versão declarava
`ACCEPTED_WITH_CAVEATS`. O script emitiu `NOT_VALIDATED`, e `cycle-acceptance § Hard gates` é
explícito: *"o verdict é computado, nunca asserido; reportar um verdict que o script não emitiu é um
review BLOCKER"*. O erro foi meu e está corrigido aqui em vez de silenciado — é o terceiro caso
neste milestone em que uma afirmação minha não sobreviveu à medição.

**Por que `NOT_VALIDATED` e não `REJECTED`:** os dois são fatos diferentes. Nada foi exercitado e
encontrado quebrado — quatro critérios passaram com evidência. O que houve é que o quinto **não pôde
ser exercitado**, porque a tela vive em outro repositório. Colapsar "não deu para checar" em
"checamos e está quebrado" é como um ciclo começa a mentir.

**O checkbox do M32 permanece `[ ]`.** Ele vira quando o AC5 for exercitável — isto é, quando o M33
entregar a tela — ou quando o milestone for re-escopado por decisão explícita para excluir um
critério que depende de repositório que ele não toca.

Os três defeitos já estão filados (#132, #133, #134), então a condição de caveats está satisfeita;
o que falta é o critério, não o registro.
